Configuration

This page lists every configuration key of a run, every key of test/TestItems.toml, and the public environment variables for configuring Runtests. Configure runs explains how to use them.

Precedence

With runtests, each value comes from the first source that sets it, in this order:

  1. the keyword of runtests,
  2. the environment variable RUNTESTS_<KEY>,
  3. the [run] table of test/TestItems.toml, or of the file that config names,
  4. the default.

An unknown key, an unknown keyword or an incorrect value is an error before any item runs. A mistake in the call is an ArgumentError. A mistake in a file or in an environment variable is a Runtests.ConfigError.

For runtests_mono, the call and environment variables still take precedence. Run-wide keys then come from [run] at the workspace root; each package's own [run] supplies its other keys. A run-wide key in the [run] of another package has no effect. What the packages share lists the run-wide keys. Run-wide keys in another package's file have no effect. Run the suites of a monorepo lists the run-wide keys.

Run keys

Each of these keys is a keyword of runtests and runtests_mono, a key of [run], and an environment variable RUNTESTS_<KEY>.

KeyDefaultValue
workers"auto"The number of workers, or "auto". Auto uses the number of CPUs, the threads of each worker and an assumed 4 GiB for each worker, at most 8. 0 runs ordinary items in the calling process; sandboxed items and items of a named profile still use workers. See Run tests.
threads"2,1"The --threads value of each worker, for example "4", "4,1" or "auto".
timeout1800Seconds for each attempt at an item.
init_timeouttimeoutSeconds for each init expression of a profile.
test_end_timeouttimeoutSeconds for each test_end expression of a profile.
artifacts_timeouttimeoutSeconds for all producers of one failed attempt together.
retries0More attempts after a failure, from 0 to 126.
failfastfalseStop the run when an item or chain still fails after its allowed retries.
item_failfastfailfastStop each item at its first failed test.
logs:issuesWhich item output the run prints: :issues, :batched, :eager or :quiet. See below.
verbosefalseInclude passing testsets in the result summary. Item output is controlled by logs.
memory_threshold0.9The fraction of machine memory in use at which new items wait. Greater than 0, at most 1.
monitortrueMonitor the memory and print progress.
monitor_interval30Seconds between progress lines when the output is not a terminal. 0 prints at each sample, five times a second.
full_stacktracesfalseKeep the frames of Runtests in the stack traces of failures.
full_namesfalsePrint long names in full, in place of a unique prefix.
testset_name"Runtests"The name of the testset that the run returns.
coveragefalseMerge line coverage into lcov.info. See Measure coverage.
seedrandomThe seed that each item combines with the name of its package and its own name. A run without a seed chooses one and prints it.

A timeout must be positive and at most 2,147,483,647 seconds. A fraction rounds up to whole seconds. Work in the calling process with workers = 0 cannot be forcibly timed out. In a TOML file or an environment variable, write a symbol as a string, for example logs = "issues".

logs

ValueEffect
:issuesPrint the output of each item that did not pass, after its DONE line.
:batchedPrint the output of every item when it ends.
:eagerPrint the output of every item while it runs, without saving it to per-item log files.
:quietPrint no item output. The output stays in the log files of the run.

An interactive session with one worker or less uses :eager by default. All other runs use :issues by default.

Call keywords

These keywords of runtests are not configuration keys and cannot go in [run]. They have no environment-variable equivalent except group, as described below.

KeywordValue
nameA String for an exact name, a Regex for a partial match, or a vector or set of exact names.
tagsA symbol, a vector of symbols that an item must carry all of, or a tag expression.
groupThe name of a group of [groups], "all" or "default". RUNTESTS_GROUP also selects a group when the call selects nothing else; see Groups.
dry_runtrue prints the plan and runs nothing.
replayThe path of a run state to run again.
configThe path of a file to read in place of test/TestItems.toml, relative to the current directory. The file must exist.
on_eventA function that the run calls with a Runtests.TestItemEvent when each attempt starts and ends.

runtests_mono also accepts packages, a list of package names or directories to include. It rejects config, because a combined run reads each package's own configuration file.

TestItems.toml

test/TestItems.toml is optional. It has these tables, and no others. A file that config names has the same form. Only a combined run reads [monorepo], from the file of the workspace root.

[run]

The [run] table takes the run keys above. Write each key as the keyword, for example timeout = 600. Write a symbol as a string, for example logs = "quiet".

[order]

KeyValue
firstA vector of exact item names. These items start first.
lastA vector of exact item names. These items start last.

On a run of the whole suite, each name must be an item of the suite. A run of a part of the suite accepts names of items outside the selection.

[groups]

Each key is the name of a group, and each value is a tag expression. all is reserved and cannot be declared. default is what a run selects when nothing else selects. A name that differs from all or default only in case is an error.

[monorepo]

The workspace root's file can have this table. It selects the packages of a combined run.

KeyDefaultValue
packagesevery package of the workspace with a suiteA vector of directories or globs, relative to the workspace root, for example ["lib/*", "."]. The packages that take part.
isolated[]A vector of directories or globs. These packages run in their own test environment, on workers of their own.

An entry that matches no package, or names a directory outside the workspace, is an error.

Profiles

Each profile is a table [profiles.<name>]. An item uses it with profile = :<name>. [profiles.default] configures the workers of every item without a profile, sandboxed or not.

KeyDefaultValue
julia_args[]A vector of command-line flags for julia, for example ["--check-bounds=yes"].
threadsthe threads of the runThe --threads value of the workers of the profile.
env{}A table of environment variables for the workers, for example { JULIA_DEBUG = "Main" }.
initnoneJulia code, as a string, that runs once in each worker before its first item, at the top level of Main. Items do not see what it defines or imports. It runs in the root of the package, or in the workspace root for a shared profile. Under workers = 0, the init of the default profile runs in the process that calls runtests, in the same directory.
test_endnoneJulia code, as a string, that runs after each item, in a new module with Test and the package in scope. It does not see the variables of the item. A failure counts toward the item.
preferencesnoneA TOML file, relative to the configuration file, whose contents go over the LocalPreferences.toml of the environment. The file must exist.
monorepo_defaultfalseOnly in the test/TestItems.toml of a workspace root. true shares the profile with the packages of the workspace, in their own runs and in combined runs. See Share a profile.

Environment variables

These environment variables configure Runtests:

VariableMeaning
RUNTESTS_<KEY>A run key, for example RUNTESTS_WORKERS=4, RUNTESTS_RETRIES=1 or RUNTESTS_SEED=0x1234. A true-or-false key takes true, false, 1, 0, yes or no. A keyword replaces it, and it replaces [run].
RUNTESTS_GROUPThe group to run when a call selects nothing else. An empty value counts as unset.
RUNTESTS_RUNSTATE_DIRThe directory of the run states, which holds a directory <run>.rundata for each run. The default is runtests/runs/ in the Julia depot, with a directory for each project.
RUNTESTS_HOSTThe name of this machine in the run states. The default is the macOS machine name, or the hostname on other systems.
RUNTESTS_ARTIFACT_DIRA directory into which a run copies its <run>.rundata directory, with its run state and logs, when it ends. A combined run puts each package's directory under a subdirectory named for the package.

Runtests sets these variables in each worker. Do not set them yourself:

VariableMeaning
RUNTESTS_RUN_IDThe ID of the run, set for each worker. Subprocesses of a worker inherit it.
RUNTESTS_WORKERThe number of the worker, as in w1.
