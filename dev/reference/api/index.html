API

This page holds the docstrings of the public API of Runtests. using Runtests brings the exported names into scope: @testitem, @testtemplate, runtests, runtestsf, chores, runtests_mono and chores_mono. It also exports Test and the macros of Test, for example @test and @testset. Reach the other public names with the Runtests. prefix, for example Runtests.on_failure.

The heading of each docstring names the module that defines the name, for example Runtests.Private.runtests. Runtests.Private and Runtests.RuntestsWorkers are internal modules. Always use the public name, for example Runtests.runtests.

Runtests.Runtests — Module
Runtests

Run a package's tests as independent test items across worker processes.

Runtests.runtests()                      # every test item under test/
Runtests.runtests("test/solver_test.jl") # one file
Runtests.runtests(name="adds numbers")   # one item
Runtests.runtests(dry_run=true)          # print the plan, run nothing

Test files live under test/ and are named *_test.jl or *_tests.jl. They contain @testitem declarations and nothing else. Shared setup code goes in test/testsetups/ as ordinary modules, which test items load with using.

Run tests

Runtests.Private.runtests — Function
runtests([paths...]; kwargs...)

Run the test items under test/. With no arguments, the project of the active environment is used.

paths narrow what is read: a directory, a test file, or file.jl:42 to select the item that line is inside, which is given without other files or directories. Several paths select what any of them does, so the package or its test/ among them is the whole suite.

Returns the run's testset, a RunTestSet named testset_name ("Runtests" unless given), holding one testset per test file. Inside an enclosing @testset it is recorded there, so the runs of several calls add up under one, told apart by their names. Outside any, an item that did not pass makes the call throw, which is what fails Pkg.test. A dry run returns nothing.

A process holds one run at a time: a call made while another is running, from another task or thread, throws and leaves that run going.

Keywords

Selection: name (String for an exact match, Regex for a partial one, or a set of exact names), tags (a symbol or vector of symbols an item must carry all of, or a string expression such as "!slow" or "juliac || serializer"), and group (the name of a tag expression [groups] of test/TestItems.toml declares, or "all", the whole suite, or "default"). The selections a call gives narrow together. A call that gives none selects the group RUNTESTS_GROUP names, when it is set, and otherwise default: the group of that name when [groups] declares one, and the whole suite when it does not. A name, tag or group the suite does not have is an error that says the nearest it does.

Execution: workers (a count, or 0 to run in this process), threads, timeout, init_timeout and test_end_timeout (a profile's init and test_end expressions are timed separately from the items, and default to timeout), artifacts_timeout (what all the producers of one failed attempt may take together, see on_failure; timeout by default), retries, failfast, memory_threshold, full_stacktraces (keep the framework's own frames in a failing item's stacktrace; trimmed by default), seed (every item draws its random numbers from this and its own name; random unless given, and printed at the start of the run).

Output: logs (:issues, :batched, :eager, or :quiet, which keeps every item's output in the run's logs and prints none of it), verbose, monitor, monitor_interval, testset_name, coverage (count which lines of src/ and ext/ the workers run, merged into lcov.info at the package's root; also RUNTESTS_COVERAGE, which a keyword overrides and which overrides the file).

State: dry_run prints the plan and runs nothing. replay names a run state (one downloaded from CI, say) and runs it again: the same items, settings, profiles, [order] and seeds, on workers given the Julia flags it recorded, with any keyword given here winning, and a warning naming each package whose version differs from the one recorded and each recorded item the suite no longer has.

Each item: on_item, a function this process calls with an ItemEvent as each attempt at an item starts, and again as it ends with what the attempt cost: its time, CPU time, compilation, garbage collection, allocations and the memory of its process. The calls come one at a time from the run's own tasks, which wait for each, so a slow function slows the run. A call that throws is reported, the function is not called again, and the tests carry on.

The execution and output settings can also be set under [run] in test/TestItems.toml, which also declares profiles, groups and forced ordering, and by a variable RUNTESTS_<SETTING> (RUNTESTS_WORKERS, say), which the run's header names: a keyword wins over the variable, and the variable over the file. config names another file to read in its place, relative to the current directory, which has to exist; nothing but this keyword makes a run read one. A mistake in the call, such as a misspelled keyword or a value out of range, is an ArgumentError; one in a file or an environment variable is a ConfigError.

Runtests.Private.runtestsf — Function
runtestsf(paths...; kwargs...)

Run the items that are failing: those whose last verdict, in the last run that ran them to one, was not a pass. Each item keeps its own, so running some of one run's failures again does not forget the others, and a run stopped before it reached an item leaves that item's verdict as it was. Only items the suite still has run: one renamed or deleted since it failed has nothing to run. With replay, the verdicts are that run's and those of the runs that started after it. See failing_items.

Every other selection narrows the failing items: name keeps those it matches, as paths, a file.jl:line, tags and group do, so nothing that is not failing runs. Each item runs with the seed it failed with, so it draws the random numbers it failed with, unless seed is given.

When no item is failing, it says so and returns nothing: running the failures until there are none is what it is for. A name that none of the failing items matches is an error.

Runtests.Private.runtests_mono — Function
runtests_mono([paths...]; packages, kwargs...)

Run the test suites of several packages of one Julia workspace in one run: one plan, one set of workers and one report. Items of different packages share workers when their profiles start workers the same way. Julia 1.12 or later.

The packages are the workspace's members that have a suite, or those that packages of a [monorepo] table in test/TestItems.toml of the workspace root lists, by directory or glob, and isolated there lists those that run in their own test environment, on workers of their own. The keyword packages narrows them to the names or directories it gives. Each package's test project has to be a member of the workspace. With no paths, the workspace of the active project; a path selects within the package that holds it, and the workspace root, a package's root or its test/ selects all of it.

Each package's items run under its own profiles, setups and settings. The settings of the run itself (workers, memory_threshold, logs, verbose, monitor, monitor_interval, full_stacktraces, full_names, testset_name, coverage, seed, failfast) come from the call, the RUNTESTS_ variables and [run] of the workspace root's test/TestItems.toml; one in another package's [run] has no effect, and the run says so. The others are each package's own: a keyword or a variable gives every package its value. name, tags and group select within each package; a group or tag only some packages have is no error. config is an error.

Before any worker starts, a using or import written in an item, a setup or a profile's init or test_end that the package's own test environment could not load stops the run, as do two packages' setups of one name. Each package gets a run state of its own, which its runtestsf, debug and next runs read as one of its own runs. Returns a RunTestSet with a testset for each package, and throws as runtests does when an item did not pass.

Runtests.Private.RunTestSet — Type
RunTestSet

What runtests returns: a testset that prints as one line. Everything else it hands to the Test.DefaultTestSet it holds, ts.testset, whose fields also read through it, so it records, finishes, counts and summarizes as that testset does. Recorded into a parent or finished inside one, it is the DefaultTestSet that goes into the parent, so no testset tree ever holds anything else.

source
Runtests.Private.ItemEvent — Type
ItemEvent

What a function given as runtests(on_item = f) is called with, in this process: once as an attempt at a test item starts, kind = :started, and once as it ends, kind = :finished. A retry is another attempt, with a call of each.

It says which item it is (name, file, line, attempt, and the package whose suite holds it, with its root, which tell apart two items of one name in a run of several packages), where it ran (worker, numbered as the run's lines number them, w1, and pid, its process), when it started or ended (time, as time() gives it), and how it went (state: :running as it starts, and then :passed, :failed, :errored, :timedout, :skipped, :broken_chain or :cancelled). pid is 0 when no process ran the attempt: the run could not start a worker for it, or it is an item of a chain whose worker died before it ran, which has worker 0 as well.

As it ends, it says what the attempt cost: elapsed, cpu (user and system time), compile, recompile (of compile) and gc in seconds, allocated in bytes, allocations, how many there were, and maxrss, the largest its process has been resident so far, in bytes. Every figure but elapsed is the whole process's, which runs one item at a time: its worker's, or with workers = 0 this process's. measured says the item measured them itself. It is false as an attempt starts, and as it ends when the run decided the outcome, as for a timeout, a lost worker, a chain cut short or a stopped run: the figures are then 0, and elapsed is how long the attempt held its worker.

Declare tests

Runtests.Private.@testitem — Macro
@testitem "name" [kwargs...] begin
    # tests
end

Declare an independently runnable group of tests.

Runtests.runtests() finds test items by parsing test files and runs each body in a fresh module on a worker process. Evaluating the macro itself — pasting an item into the REPL, or includeing its file — runs that one item the same way in this session, or on a worker of its own when it is sandboxed.

The body runs at the top level of its module with the REPL's soft scope, as in ReTestItems, so its variables are untyped globals. That matters to a test that measures allocations. Julia measures a plain call such as @allocated f(x, y), whose function and arguments are names or literals, from inside f. Anything else, such as Mod.f(x), a keyword argument or a begin block, it measures where it stands, which then includes reaching the globals. Put such a measurement in a let block, where the variables are local:

@testitem "summing allocates nothing" begin
    let
        x = rand(10)
        @test @allocated(sum(x; init = 0.0)) == 0
    end
end

Keyword arguments must be literals, except skip, which may be any expression and is evaluated on the worker before the body, with Test and the package in scope. It must give a Bool, and an error in it is the item's error.

KeywordMeaning
tags=[:a, :b]tags used for filtering
timeout=Nseconds before the item is killed; overrides the run default
retries=Noverrides the run default; a chain retries from its first item
skip=exprBool, or an expression evaluated on the worker before the body
failfast=truestop this item at its first failure
chain=:symitems sharing a chain run in sequence on one worker
sandbox=truerun alone in a process that is torn down afterwards
profile=:namerun on the workers of [profiles.name] of TestItems.toml

sandbox and profile combine: sandbox=true profile=:name runs alone in a process of that profile. Neither chooses the item's packages: it runs in the environment of the innermost directory between its file and test/ with a Project.toml of its own, and otherwise in the test environment.

Runtests.Private.@testtemplate — Macro
@testtemplate "name $x" [kwargs...] for x in xs
    # tests, with `$x` where the value of `x` goes
end

Declare a test item per iteration of the loop, in a test template: a file test/testtemplates/*_tests_template.jl, which chores runs in a process with the test environment and the setups, and expands into the test file of its name without _template, in test/.

# test/testtemplates/periods_tests_template.jl, expanded into test/periods_tests.jl
@testtemplate "doubling a $P of $n" for P in (Dates.Day, Dates.Month), n in 1:2
    using Dates
    @test $P($n) + $P($n) == $P(2 * $n)
end

The loop runs as Julia's does, in a module holding Test, the package and each package the body imports, by name and nothing more: it says Dates.Day where the item, after its using Dates, says Day. The name interpolates each iteration's values, printed as the item would. A template holds @testtemplates and nothing else: an ordinary @testitem goes in a test file, and a list several templates share in a setup module. In the keywords and the body, $x puts the value of the loop variable x there, written as code, as Threads.@spawn takes $x: repr(x) as the item's module sees it with the body's using and import statements, which has to evaluate back to an equal value there. Nothing binds x in the item, so x written without its $ is refused unless the body binds it itself, as x = $x does.

In the keywords, a $(...) is computed as the template expands, once per iteration among the same names, and its value written the same way: skip = $(x in MySetup.KNOWN_BAD) is skip = true or skip = false in each item. Outside a $(...) a keyword is the item's, evaluated as it runs. In the body, a $ before anything but a loop variable is left as it is, for a macro of the body's own, and so is every $ inside a quoted expression.

Evaluated anywhere but in a template expanded by chores, it throws.

Maintain the suite

Runtests.Private.chores — Function
chores([path]; dry_run = false, config = nothing)

Look after a package's suite: do what needs no person, then say what does.

  • test items and test/TestItems.toml: everything a run would refuse to start on, such as a syntax error, a name declared twice, a setting it does not accept, an [order] entry naming no item or an unknown profile. Reported, never changed.
  • config files given as config, a path or several, relative to the current directory: each checked as a run given it would check it, as well as test/TestItems.toml.
  • test setups: what setups_to_packages would do, making packages of the setups that are not and adding to their [deps] what they have come to import.
  • test templates: each test/testtemplates/*_tests_template.jl expanded into the test file of its name in test/, in a process with the test environment, and the expansion of a template that is gone deleted. Every template is expanded, since what its code computes can change while its text does not; a dry run reads the expansions' stamps instead and runs nothing. An expansion edited by hand, and a test file in a template's way that chores did not write, are left to a person.
  • run states: this machine's are pruned as a run prunes them, the same ones and no others (see prunable_runstates), with their logs; and those of a format older than any this version reads are deleted. One recorded elsewhere, a CI artifact say, and one that cannot be read otherwise are never deleted.
  • checkouts that are gone: when the project keeps its run states in the default location, the run states there of every checkout that no longer exists, as sweep_runstate_dirs finds them, the directories that held them with them. Nothing else deletes them: a run reads its own directory and no other.

Returns whether nothing is left to do. Having done the rest, it throws a ChoresError when something is left that a person has to fix, and otherwise returns true; so Runtests.chores(); Runtests.runtests() stops before any test runs on a suite a person has to fix first. With dry_run = true it changes nothing and never throws, and returns whether there is nothing to do, neither for a person nor for it. path finds the package as it does for runtests.

source
Runtests.Private.chores_mono — Function
chores_mono([root]; dry_run = false)

chores for each package of a combined run, as runtests_mono finds them, and what a combined run needs on top, in one report with paths from the workspace root. Before any package's chores change a file, it stops for what would stop a combined run and what no chore fixes: two setups of one name, one dependency name declared with two UUIDs, and two packages that set one preference differently. Then it does each package's chores in turn, and the run states of checkouts that are gone once. After them, the report says which items can share a worker: the groups of profiles whose workers are alike, a profile that the workspace shares (monorepo_default) with the packages that use it, and each package's own. It checks each using and import written in the items, setups and profiles of each package that shares workers against that package's own test environment, once the setups' packages have their new dependencies. And it says of a package whose test/runtests.jl does more than call runtests that a combined run does not run that file.

Returns and throws as chores does. A ChoresError names the packages whose chores already ran, and so may have changed files.

Runtests.Private.setups_to_packages — Function
setups_to_packages([path])

Make every module in the package's test/testsetups/ a package of its own, so that its precompile cache is kept per checkout and per set of Julia flags instead of in one file that each of them rewrites. Name.jl moves to Name/src/Name.jl, beside a Name/Project.toml that gives it a UUID and lists the packages it imports as its [deps]. Test items load it with using Name, as before.

A package can import only what its [deps] list, so run this again after a setup starts importing something new: it adds what is missing, changes nothing else, and keeps the UUIDs. An import it cannot see, such as one in code that the setup generates or evaluates as it loads, goes into [deps] by hand.

In a moved file, @__DIR__ becomes pkgdir(MyPkg, "test", "testsetups"), for the package under test, which names the directory the file was in from anywhere, the REPL included; joinpath(@__DIR__, "..", "data") becomes pkgdir(MyPkg, "test", "data"). A setup that does not import the package gets an import MyPkg for it. Nothing is written unless every setup can be converted: an import that neither the test environment nor the standard library provides, a relative include and @__FILE__ are reported instead, all of them at once.

path finds the package as it does for runtests.

Inside a test item

current_testitem() returns a TestItemInfo with the fields name, file, line, attempt and profile.

Runtests.RuntestsWorkers.current_testitem — Function
current_testitem() -> Union{Nothing,TestItemInfo}

The test item this task is running inside, or nothing.

The value is dynamically scoped, so tasks spawned by the test item see it and a task created before the item started — a long-lived service started in a profile's init expression, say — does not. For that case, and for subprocesses, use in_test_run.

This is a hook for test infrastructure: temporary directories, fixture paths, switching off telemetry. Library code that changes what it does because it detects that it is under test stops testing the library.

in_test_run() -> Bool

Whether this process was started by a Runtests run. Unlike in_testitem this is process-level: it is visible to every task and inherited by subprocesses.

Runtests.RuntestsWorkers.on_failure — Function
on_failure(f) -> nothing

Register f to be called with a directory of its own if this attempt at the test item fails, and not otherwise. Producers are called once each, in the order registered, after the item and its profile's test_end have finished and the verdict is recorded, so they see the values they refer to as they are then. What they write is kept with the attempt's evidence; what they throw, or a @test in them that fails, is reported there and never changes the verdict.

Only in the body of a running test item, or in a task it starts and waits for.

source
Runtests.RuntestsWorkers.artifacts_dir — Function
artifacts_dir() -> String

The directory this attempt at the test item keeps outputs in, made the first time it is asked for. What is written there is deleted if the attempt passes and kept if it fails. The same directory every time within one attempt; another for each attempt.

Only in the body of a running test item, or in a task it starts and waits for.

At the REPL

Runtests.Private.activate — Function
activate([paths...]) -> String

Make this session look the way a test item's worker does: the package's test environment active and test/testsetups/ on LOAD_PATH, so using MySetup and test-only dependencies work at the REPL. Returns the environment's path; deactivate undoes it.

source
Runtests.Private.activate_mono — Function
activate_mono([root]) -> String

activate for the packages of a workspace, as runtests_mono runs them: the union environment of their test dependencies active, and the setups of each package that shares workers on LOAD_PATH, so that the REPL loads what a shared worker loads. An isolated package is not part of it; activate it on its own. A test item runs as an item of the package whose directory holds its file, as on a shared worker: in the union environment, with its package loaded, in its package's root. For an item pasted at the REPL, that is the package whose directory holds the REPL's current directory. Two setups of one name stop it before anything changes. deactivate undoes it. Returns the active project.

deactivate()

Undo activate: restore the environment that was active and take the setups back off LOAD_PATH. Does nothing if Runtests is not active.

Runtests.Private.debug — Function
debug([item]; seed) -> Test.AbstractTestSet

Step into one test item with Debugger.jl: using Debugger first. item picks it: its exact name; a Regex that matches the name of that item and no other; or a path, as runtests takes one, relative to the current directory: file.jl:line for the item that line is inside, or a test file or directory that holds that item and no other. What picks no item, or several, is an error that says what it found. Without item it is the most recent failure among the items that are failing (see runtestsf): of those that failed, errored or timed out, the one whose failure was recorded last, with the seed it failed with, so it draws the random numbers it failed with. When no run of the project is recorded, or no item is failing, there is nothing to step into, and it says so.

The item runs here, in this process, as a run would run it: its module and imports, the test environment, or the environment of the directory its file is in, and the setups, and its profile's env, init and test_end. Its body is a function the debugger enters at the body's first call. What cannot be part of a function, using and struct among it, has run by then. Only this item runs: the items before it in a chain do not.

What this process cannot give the item is listed before it starts: a profile's julia_args, threads and preferences, a process of its own, and the keywords only a scheduler honours. seed is a run's, as runtests takes and prints it, so the item draws the random numbers it drew in that run.

Returns the item's testset. Leaving the debugger before the item has finished records an error, since the rest of it did not run.

Editors

Runtests.Private.serve — Function
serve(path = "."; config = nothing, input = stdin, output = stdout)

Drive the test suite of the package at path from an editor: read commands from input and write events to output, one JSON object per line, until input ends or a shutdown command arrives; a run still going is cancelled first. The commands are list, run, cancel and shutdown: each an object naming its command, with an id that the events answering it carry, and for run the items to run, each a package and a name, or their names, and the options to run them with (RUN_OPTIONS). config names a file every listing and run of the session reads in place of test/TestItems.toml, relative to the current directory.

Serving over this process's own stdout takes it over for the rest of the process: everything else written there, by the run, by Pkg or by C libraries, goes to stderr from then on, so that the stream holds events and nothing else.

source

serve_mono(root = nothing; input = stdin, output = stdout)

serve for the packages of a workspace, as runtests_mono runs them: the listing has the items of every package, each with its package, and a run is a combined run. A run names its items as keys of a package and a name.

Exceptions

Runtests.Private.ScanFailure — Type
ScanFailure

Thrown when test files cannot be read as a suite: a syntax error, a name declared twice, a Julia file that is not a test file. errors holds every problem found, each with its file, line and msg, so one run reports them all.

source
Runtests.Private.NoTestsError — Type
NoTestsError

Thrown when there is nothing to run: no test files, no item the selection matched, or no failures left to re-run. msg says which.

source
Runtests.Private.ConfigError — Type
ConfigError

Thrown when a run cannot be set up as asked: a keyword or TestItems.toml setting it does not accept, a profile or run state it cannot use, a test setup that does not precompile. msg says what and where.

source
Runtests.Private.ChoresError — Type
ChoresError

Thrown by chores once it has done what it could, when what is left needs a person: the problems its report names. msg counts them.
